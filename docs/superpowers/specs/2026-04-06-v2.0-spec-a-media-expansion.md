# ClipSlim v2.0 — Spec A: Media Expansion

## Overview

Extend ClipSlim's optimization engine to handle video, GIF, SVG, and lossless compression. This is the foundation for Specs B and C — the Share extension, CLI tool, and creative tools all depend on these new media types being supported.

## Features

### 1. Video Compression (H.264/H.265)

**Goal:** Compress video files from clipboard, folder watcher, and drop zone using hardware-accelerated encoding.

**Implementation:**
- New `ClipSlim/Services/VideoOptimizer.swift` — `Sendable` singleton matching `ImageOptimizer` pattern
- `VideoOptimizationConfig` struct: codec (`h264`/`hevc`), quality (0.0-1.0), maxResolution (1080/1440/2160), bitrateTarget (optional Int, in kbps), stripMetadata (Bool)
- Uses `AVAssetExportSession` with appropriate preset — hardware acceleration via VideoToolbox is automatic on Apple Silicon
- Temp file workflow: write to temp dir → read result → clean up (video can't be held in memory)
- Output format: always `.mp4` (universal compatibility)
- Timeout: 60s base + 1s per MB above 100MB. Input cap: 500MB
- `VideoOptimizationResult` struct: originalSize, optimizedSize, duration, codec, resolution (width/height), originalBitrate, optimizedBitrate

**Clipboard detection:**
- Extend `ClipboardWatcher` to check for `public.movie` / `public.mpeg-4` UTTypes
- Route to `ProcessingCoordinator.processVideoData()`

**Folder/Drop Zone:**
- Extend `ProcessingCoordinator.processFileURL()` to route `.mp4`, `.mov`, `.m4v` to VideoOptimizer
- Drop Zone accepts video files (add to supported UTTypes)

**Settings — New "Video" tab:**
- Uses `VibeSettingsPage` > `VibeSettingsCard` > `VibeHintText` pattern
- Section: "Video Compression" — enable toggle, codec picker (H.264/H.265 segmented), quality slider (0.4-1.0), max resolution picker (1080p/1440p/4K)
- Section: "GIF" — max colors (64/128/256), frame skip toggle, video-to-GIF FPS (5/10/15)
- All settings via `AppSettings` with `didSet` UserDefaults pattern

**Overlay:**
- Video results show: duration, resolution, codec, bitrate delta, file size delta
- Uses same `OverlayItem` → `OverlayView` flow
- Metrics use `VibeCheckTheme.Typography.monospacedBold` for numbers
- Neon cyan for savings stats, orange for accents

**Tests:**
- Create test MP4 programmatically with `AVAssetWriter` (1s, 320x240, solid color frames)
- Verify output smaller than input
- Verify H.265 codec produces HEVC output
- Verify max resolution constrains output dimensions
- Verify timeout triggers for stuck exports
- Edge: video with no audio track
- Edge: very short video (<1s)
- Integration: ProcessingCoordinator routes `.mp4` to VideoOptimizer
- Integration: ClipboardWatcher detects `public.movie`

### 2. GIF Optimization + Video-to-GIF

**Goal:** Optimize existing GIFs and convert short videos to GIF.

**Implementation:**
- New `ClipSlim/Services/GIFOptimizer.swift` — `Sendable` singleton
- `GIFOptimizationConfig` struct: maxColors (64/128/256), frameSkip (0 = none, 2 = every other, etc.), maxDimension (Int), videoToGifFPS (5/10/15)
- Two public methods:
  - `optimizeGIF(data: Data, config: GIFOptimizationConfig) async throws -> (data: Data, result: GIFOptimizationResult)`
  - `videoToGIF(url: URL, config: GIFOptimizationConfig) async throws -> (data: Data, result: GIFOptimizationResult)`
- `GIFOptimizationResult` struct: originalSize, optimizedSize, frameCount, originalFrameCount, colorCount, duration

**GIF optimization pipeline:**
1. Read frames via `CGImageSourceGetCount` + `CGImageSourceCreateImageAtIndex`
2. Read frame delays from `kCGImagePropertyGIFDictionary` / `kCGImagePropertyGIFDelayTime`
3. Optionally skip frames (keep every Nth)
4. Resize frames if larger than maxDimension
5. Write via `CGImageDestinationCreateWithData` with `com.compuserve.gif` UTType
6. Set frame delays on each frame via `kCGImagePropertyGIFDictionary`
7. Process in batches of 50 frames — read, transform, write, release (never hold all frames in memory)

**Video-to-GIF pipeline:**
1. `AVAssetImageGenerator` with `requestedTimeToleranceBefore/After` set for exact timing
2. Generate frames at target FPS (default 10)
3. Cap at 15 seconds (150 frames at 10 FPS) — warn user if video is longer
4. Process frames streaming — generate and write each before generating next
5. Same GIF encoding as above

**Clipboard detection:**
- Detect `com.compuserve.gif` UTType in `ClipboardWatcher`

**Input cap:** 50MB for GIF optimization, 15s for video-to-GIF

**Tests:**
- Create multi-frame test GIF programmatically
- Verify optimization reduces size
- Verify frame count preserved (no skip) and reduced (with skip)
- Verify color quantization produces smaller output
- Verify frame delays preserved
- Edge: single-frame GIF, transparent frames
- Video-to-GIF: valid GIF from MP4, FPS controls frame count, max dimensions respected

### 3. SVG Optimization

**Goal:** Strip unnecessary data from SVG files while preserving visual appearance.

**Implementation:**
- New `ClipSlim/Services/SVGOptimizer.swift` — `Sendable` singleton
- Uses Foundation `XMLParser` — no external dependencies (consistent with pure Apple frameworks convention)
- `SVGOptimizationResult` struct: originalSize, optimizedSize, elementsRemoved (Int), commentsRemoved (Int)

**Optimization pipeline (in order):**
1. Strip XML comments (`<!-- ... -->`)
2. Strip `<metadata>` element entirely
3. Strip editor namespaces: `xmlns:inkscape`, `xmlns:sodipodi`, `xmlns:dc`, `xmlns:cc`, `xmlns:rdf`, `xmlns:ns0` and all elements/attributes using those prefixes
4. Remove empty `<g>` elements (no children)
5. Round numeric attributes (coordinates, dimensions) to 2 decimal places
6. Collapse excessive whitespace in path `d=""` attributes
7. Serialize back to string with minimal whitespace

**Does NOT modify:** `<style>` blocks, `viewBox`, visual attributes (fill, stroke, opacity), `<defs>` with referenced IDs, any element that could affect rendering.

**Clipboard detection:**
- Detect `public.svg-image` UTType

**Returns:** `Data` (UTF-8 encoded SVG string)

**Tests:**
- Hand-crafted SVG strings with comments, metadata, Inkscape namespaces, empty groups, verbose coordinates
- Verify each transformation independently
- Verify `<style>` and `viewBox` preserved
- Verify output is valid XML
- Edge: already-optimized SVG returns unchanged

### 4. Lossless Compression Mode

**Goal:** Reduce file size without any quality loss — new preset option.

**Implementation:**
- Add `OptimizationPreset.lossless` case to existing enum
- Properties: quality 1.0, maxDimension Int.max, stripMetadata via user's MetadataPolicy, allowTransparencyLoss false
- In `ImageOptimizer.optimize()`: when quality == 1.0, use PNG for alpha images, JPEG at quality 1.0 for non-alpha (Apple's encoder still optimizes Huffman tables)
- **Skip guard:** if `optimizedSize >= originalSize`, return original data unchanged with `savingsPercentage: 0`
- MetadataPolicy still applied — stripping metadata is the primary source of savings in lossless mode

**Settings UI:**
- Add "Lossless" as 5th option in `PresetButtonGroup` (after Custom)
- Description: "No quality loss — reduces size through metadata stripping and encoder optimization"
- `VibeCheckTheme` consistent — uses same `PresetButtonGroup` component

**Tests:**
- Lossless preset has quality 1.0, maxDimension Int.max
- Lossless JPEG output not larger than input (with skip guard)
- Lossless PNG preserves alpha
- Skip guard returns original when optimized is larger
- MetadataPolicy applied in lossless mode

## ProcessingCoordinator Routing

Extend `OptimizableFileType` enum with new cases:

```
enum OptimizableFileType {
    case image
    case pdf
    case video    // NEW
    case gif      // NEW
    case svg      // NEW
}
```

`ProcessingCoordinator` routing logic:
1. Detect type from data/URL
2. Route: image → existing path, pdf → existing path, video → `processVideoData()`, gif → `processGIFData()`, svg → `processSVGData()`
3. Each media type has its own processing method to keep the coordinator file manageable

`ClipboardWatcher` detection order: PDF → video → GIF → SVG → image (most specific first)

## Performance Considerations

| Feature | Risk | Mitigation |
|---------|------|------------|
| Video | CPU/GPU intensive, slow for large files | AVAssetExportSession hardware accel, Task.detached(.utility), timeout, 500MB cap |
| GIF (optimize) | Memory from loading all frames | Process in batches of 50 frames, 50MB input cap |
| GIF (video-to) | Many frames from long videos | Cap at 15s, stream-process frames |
| SVG | Minimal — small text files | None needed |
| Lossless | Output may be larger | Skip guard returns original if no savings |

## Post-v1.1 Roadmap Position

This is Spec A of 3 for v2.0:
- **Spec A (this):** Media Expansion — Video, GIF, SVG, Lossless
- **Spec B:** Workflows & Automation — Global shortcuts, Share extension, CLI, Batch rename

Spec B depends on Spec A (Share/CLI need to handle new media types).
