# ClipSlim v2.0 — Spec C: Creative Tools

## Overview

Add watermarking (text + image) and social media resize presets. These are output transformation features that sit on top of the existing optimization pipeline. Independent of Specs A and B — can be built in parallel.

## Features

### 1. Watermarking (Text + Image)

**Goal:** Apply configurable watermarks to optimized images — text or image overlay with position, opacity, and tiling control.

**Implementation:**
- New `ClipSlim/Services/WatermarkService.swift` — `Sendable` singleton
- Single public method: `apply(to imageData: Data, config: WatermarkConfig) throws -> Data`
- Text rendering: `CoreText` `CTFramesetterCreateWithAttributedString` → draw into `CGContext` at computed position
- Image watermark: load from path via `CGImageSource`, composite with `CGContext.draw()` at target opacity using `CGContext.setAlpha()`
- Cache loaded watermark `CGImage` in service (load once, reuse across optimizations)

**WatermarkConfig struct:**
```
struct WatermarkConfig: Codable, Sendable {
    var enabled: Bool
    var type: WatermarkType           // .text or .image
    var text: String                  // for text type
    var fontName: String              // system font family name
    var fontSize: CGFloat             // relative to image width
    var color: CodableColor           // RGBA with opacity
    var imagePath: String             // for image type
    var imageOpacity: CGFloat         // 0.0-1.0
    var position: WatermarkPosition   // 9-grid enum
    var margin: CGFloat               // pixels from edge
    var tilingEnabled: Bool           // repeat across image
    var tilingSpacing: CGFloat        // pixels between tiles
}
```

**WatermarkPosition enum (9-grid):**
```
topLeft      topCenter      topRight
middleLeft   center         middleRight
bottomLeft   bottomCenter   bottomRight
```

Position maps to CGPoint given image dimensions and margin.

**Pipeline position:**
- Applied in `ProcessingCoordinator` AFTER optimization, BEFORE writing to clipboard/disk
- Flow: detect → optimize → watermark (if enabled) → write
- NOT applied when: lossless mode, PDF, video, GIF, SVG, or watermark disabled
- Tiling: compute grid positions to fill image, draw at each point. Cap at 100 tiles max.

**Settings — New "Watermark" tab (between PDF and Support):**
- Uses `VibeSettingsPage` > `VibeSettingsCard` > `VibeHintText` pattern
- Cards:
  1. "Watermark" — enable toggle, type picker (Text/Image segmented)
  2. "Text Settings" (shown when type=text) — text field, font picker (`NSFontManager.shared.availableFontFamilies`), size slider, `ColorPicker` with opacity
  3. "Image Settings" (shown when type=image) — file picker button, opacity slider
  4. "Position" — visual 3x3 grid of buttons, selected highlighted in neon cyan
  5. "Tiling" — enable toggle, spacing slider
  6. "Preview" — live 256px-wide thumbnail rendered via WatermarkService, debounced 300ms
- All values stored in `AppSettings` as JSON string (`watermarkConfigData`) with `didSet` UserDefaults pattern

**Files:**
- Create: `ClipSlim/Services/WatermarkService.swift`
- Create: `ClipSlim/Models/WatermarkConfig.swift` (config + WatermarkType + WatermarkPosition + CodableColor)
- Create: `ClipSlim/Views/Settings/WatermarkTab.swift`
- Modify: `ClipSlim/Views/Settings/SettingsView.swift` (add tab)
- Modify: `ClipSlim/Models/AppSettings.swift` (watermarkConfigData property)
- Modify: `ClipSlim/Coordinators/ProcessingCoordinator.swift` (apply watermark step)

**Tests:**
- Text watermark produces valid output (non-empty, data changed)
- Image watermark composites at correct opacity
- All 9 positions place watermark in expected region
- Tiling fills image with multiple instances
- Margin pushes watermark inward from edges
- Disabled config returns original data unchanged
- Not applied to PDF/video/GIF/SVG
- Not applied in lossless mode
- Edge: very small image (<64px) skipped gracefully
- Edge: empty text string returns original

### 2. Social Media Resize Presets

**Goal:** One-click resize to platform-specific dimensions for social media.

**Presets:**

| Platform | Name | Dimensions | Aspect Ratio |
|----------|------|-----------|--------------|
| Twitter/X | Post | 1600x900 | 16:9 |
| Twitter/X | Header | 1500x500 | 3:1 |
| Instagram | Square | 1080x1080 | 1:1 |
| Instagram | Story | 1080x1920 | 9:16 |
| Instagram | Landscape | 1080x566 | 1.91:1 |
| LinkedIn | Post | 1200x627 | 1.91:1 |
| LinkedIn | Cover | 1584x396 | 4:1 |
| Facebook | Post | 1200x630 | 1.91:1 |
| Facebook | Cover | 851x315 | 2.7:1 |
| YouTube | Thumbnail | 1280x720 | 16:9 |
| Open Graph | OG Image | 1200x630 | 1.91:1 |
| Favicon | Favicon | 512x512 | 1:1 |

**Implementation:**
- New `ClipSlim/Models/SocialMediaPreset.swift` — enum with `CaseIterable`
- Properties: `displayName`, `platform`, `width`, `height`
- Static grouping: `SocialMediaPreset.grouped` returns `[(platform: String, presets: [SocialMediaPreset])]`
- NOT a new optimizer — feeds dimensions into existing `ImageOptimizer` resize via `targetDimensions` on `OptimizationConfig`

**Crop-to-fill:**
- When target aspect ratio differs from source, center-crop to fit (no letterboxing)
- New method in `ImageOptimizer`: `cropToFill(data: Data, width: Int, height: Int) throws -> Data`
- Same CGContext approach as existing `cropToSquare`, generalized to arbitrary aspect ratio
- Calculate center crop rect: if source wider, crop sides; if source taller, crop top/bottom

**UI integration:**
- Quick Resize Panel (from Spec B): add "Social" tab alongside "Custom" — shows preset grid grouped by platform
- Overlay resize section: add dropdown with social presets as quick-select options
- No new settings tab — presets are built-in constants

**Files:**
- Create: `ClipSlim/Models/SocialMediaPreset.swift`
- Modify: `ClipSlim/Services/ImageOptimizer.swift` (add `cropToFill`)
- Modify: `ClipSlim/Views/QuickResizePanel.swift` (Social tab — depends on Spec B)
- Modify: `ClipSlim/Views/OverlayView.swift` (social preset dropdown in resize section)

**Tests:**
- All 12 presets have correct non-zero dimensions
- All presets have non-empty displayName and platform
- CaseIterable count matches expected (12)
- Grouped by platform produces correct groups
- cropToFill: 1920x1080 → 1080x1080 produces square from center
- cropToFill: 1080x1080 → 1920x1080 produces landscape from center
- cropToFill: output dimensions exactly match target
- cropToFill: transparent images preserve alpha
- Edge: target larger than source handled gracefully

## UI Consistency Requirements

- **Watermark tab:** `VibeSettingsPage` > `VibeSettingsCard` > `VibeHintText`
- **Position grid:** 3x3 button grid, selected = `neonCyan` border + fill, unselected = `surface` color
- **Color picker:** Native SwiftUI `ColorPicker` with opacity support
- **Font picker:** `Picker` with system font families, monospaced preview of selected font
- **Preview thumbnail:** `VibeCheckTheme.CornerRadius.sm`, subtle border, dark background
- **Social preset grid:** Grouped sections with platform headers in `.textSecondary`, preset buttons with dimensions in `.monospacedBold`
- **Typography:** All metrics/dimensions in `VibeCheckTheme.Typography.monospacedBold`
- **Spacing:** `VibeCheckTheme.Spacing` throughout

## Performance Considerations

| Feature | Risk | Mitigation |
|---------|------|------------|
| Text watermark | Negligible | Single CTFramesetter draw call |
| Image watermark | Loading external file | Cache CGImage in service, load once |
| Tiling | Many draw calls | Cap at 100 tiles, warn above |
| Social presets | Crop + resize | Reuses ImageOptimizer, no new concern |
| Live preview | Re-render on settings change | 300ms debounce, 256px thumbnail |
