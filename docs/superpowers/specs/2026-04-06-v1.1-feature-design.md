# ClipSlim v1.1 Design Spec — "The Competitive Closer"

## Overview

Six features targeting broad appeal (web devs, power users, content creators) that close the most critical competitive gaps — primarily against Clop, Squash, and Optimage.

## Features

### 1. Before/After Visual Comparison

**Goal:** Let users visually verify optimization quality before committing.

**Implementation:**
- Draggable slider divider inside the existing 392px overlay panel (not side-by-side — saves space)
- Toggle button in overlay toolbar, default off
- Uses `Canvas` or `GeometryReader` with clip masks for the slider effect
- Downsampled previews (max 800px wide) via `CGImageSourceCreateThumbnailAtIndex` to avoid memory spikes
- Full-res only loaded on explicit zoom

**Files affected:**
- New: `ClipSlim/Views/Components/ComparisonView.swift`
- Modified: `OverlayView.swift`, `OverlayService.swift`, `ProcessingCoordinator.swift`

**Tests:**
- `ProcessingCoordinator` exposes both original and optimized data
- Slider clips correctly at 0%, 50%, 100%

---

### 2. AVIF Format Support

**Goal:** Add AVIF as an output format — table-stakes for web developers in 2026.

**Implementation:**
- Add `.avif` case to `ImageFormat` enum with UTType `public.avif`
- Apple's `ImageIO` on macOS 14+ supports AVIF via `CGImageDestination` — same pipeline as existing formats
- Add AVIF to format override picker in `PresetsTab` and overlay one-off format selector
- Include in `ImageClassifier` recommendation logic — prefer AVIF over WebP for photographic content when `preferWebP` is off
- AVIF is NOT the Smart Format Detection default (encoding is 2-5x slower than JPEG) — manual opt-in only

**Files affected:**
- Modified: `ImageFormat.swift`, `ImageOptimizer.swift`, `FormatSelector.swift`, `PresetsTab.swift`, `OverlayView.swift`

**Tests:**
- Valid AVIF output from JPEG/PNG input
- `FormatSelector` recommends AVIF for photographic content when enabled
- `ImageFormat` round-trips correctly (rawValue, UTType, file extension)
- Graceful fallback to JPEG if AVIF encoding fails

---

### 3. Clipboard History

**Goal:** Scrollable list of recent optimizations with re-copy capability.

**Implementation:**
- Reuse existing `ClipboardHistoryEntry` SwiftData model
- Add `thumbnailData: Data?` property (~5KB JPEG thumbnail for fast list rendering)
- Full image data stored as files on disk in `Application Support/ClipSlimHistory/`, referenced by UUID — NOT in SwiftData (avoids 500MB+ database bloat)
- Cap at 50 entries, oldest evicted first, disk files pruned on eviction
- Presented as `NSPanel` (consistent with Drop Zone pattern), not popover
- Each entry: thumbnail, original/optimized size, delta percentage, timestamp
- Tap to re-copy (choice of original or optimized)
- "Clear History" button with confirmation
- Accessible from menubar dropdown via "History" item

**Files affected:**
- New: `ClipSlim/Views/ClipboardHistoryView.swift`
- Modified: `ClipboardHistoryService.swift`, `MenuBarView.swift`, `ClipboardHistoryEntry.swift` (SwiftData migration)

**Tests:**
- Store and retrieve entries with thumbnails
- 50-entry cap enforced (oldest evicted)
- Re-copy produces correct pasteboard content
- SwiftData migration from existing schema

### 4. Shortcuts.app Integration

**Goal:** Expose image optimization as a Shortcuts action for user-built automations.

**Implementation:**
- New `ShortcutsIntents/` group using `AppIntents` framework
- Single intent: `OptimizeImageIntent` conforming to `AppIntent`
  - Parameters: `file: IntentFile` (required), `preset: OptimizationPresetEnum` (optional, defaults to current), `outputFormat: ImageFormatEnum` (optional)
  - Returns: optimized `IntentFile`
- Register via `AppShortcutsProvider`
- Uses `@Dependency` to access optimizer — no full app UI launch needed
- 30-second timeout on optimization task to prevent Shortcuts hangs

**Files affected:**
- New: `ClipSlim/ShortcutsIntents/OptimizeImageIntent.swift`, `ClipSlim/ShortcutsIntents/ShortcutsProvider.swift`
- Modified: Xcode project (add AppIntents capability)

**Tests:**
- Intent performs optimization and returns valid file
- Preset parameter override works
- Invalid/unsupported input returns clear error
- Background execution without main app running

---

### 5. Finder Quick Action

**Goal:** Right-click any image in Finder to optimize with ClipSlim.

**Implementation:**
- New Action Extension target in Xcode project
- Extension receives selected file URLs, applies current preset, writes optimized files alongside originals (or to configured output folder)
- Requires shared code: extract optimizers into `ClipSlimCore` framework
  - Contains: `ImageOptimizer`, `PDFOptimizer`, `ImageFormat`, `OptimizationPreset`, `FormatSelector`, `ImageClassifier`, `QualityScorer`, `MetadataPolicy`
  - No UI, no SwiftData, no services
  - Both main app target and extension target link against it
  - Future-proofs for CLI tool (v1.8)
- Sequential file processing in extension (lower memory limits than main app)
- Progress indication for multi-file selections
- Graceful error on memory pressure

**Files affected:**
- New: `ClipSlimCore/` framework target, `ClipSlimAction/` extension target
- Modified: Xcode project (two new targets), existing optimizer files moved to framework

**Tests:**
- Shared framework optimizers produce identical output to current main app
- Extension receives file URLs and writes output correctly
- Read-only source folder error handling

---

### 6. Selective Metadata Control

**Goal:** Granular metadata stripping — keep copyright while removing GPS/camera info.

**Implementation:**
- Replace boolean `stripMetadata` in `AppSettings` with `MetadataPolicy` struct:
  ```swift
  struct MetadataPolicy: Codable, Sendable {
      var mode: MetadataMode // .keepAll, .stripAll, .selective
      var keepCopyright: Bool // default true
      var keepAuthor: Bool // default true
      var stripGPS: Bool // default true
      var stripCameraInfo: Bool // default true
  }
  ```
- In `ImageOptimizer`, selectively copy/remove `CGImageProperties` dictionary keys (`kCGImagePropertyGPSDictionary`, `kCGImagePropertyExifDictionary`, `kCGImagePropertyIPTCDictionary`, etc.) based on policy
- Legacy migration: `stripMetadata = true` → `.stripAll`, `false` → `.keepAll`
- Settings UI: expand metadata toggle in `PresetsTab` into disclosure group with individual checkboxes

**Files affected:**
- New: `ClipSlim/Models/MetadataPolicy.swift`
- Modified: `AppSettings.swift`, `ImageOptimizer.swift`, `PresetsTab.swift`

**Tests:**
- Preserves copyright while stripping GPS from test image with known EXIF
- `stripAll` removes everything, `keepAll` preserves everything
- Legacy boolean migration works correctly
- No crash on images with no metadata

## Structural Decision: ClipSlimCore Framework

Extracting optimizers into a shared framework is the biggest structural change. This serves:
- v1.1: Finder Quick Action extension
- v1.8 (future): CLI tool
- General: cleaner separation of pure optimization logic from app services

**What moves to ClipSlimCore:**
- `ImageOptimizer`, `PDFOptimizer`
- `ImageFormat`, `OptimizationPreset`, `MetadataPolicy`
- `FormatSelector`, `ImageClassifier`, `QualityScorer`
- `PipelineStep`, `OptimizationResult`

**What stays in the main app:**
- All services (clipboard, folder, drop zone, overlay, notifications)
- All views and view models
- SwiftData models and persistence
- Settings, theme, coordinators

## Performance Considerations

| Feature | Risk | Mitigation |
|---------|------|------------|
| Before/After | Memory from dual image loading | Downsampled previews, full-res only on zoom |
| AVIF | 2-5x slower encoding | Manual opt-in only, not auto-default |
| Clipboard History | DB bloat from 50 image pairs | Thumbnails in SwiftData, full images on disk |
| Finder Quick Action | Extension memory limits | Sequential processing, graceful bail |
| Shortcuts | Background execution timeout | 30-second timeout with clear error |
| Shared Framework | Build time increase | Keep framework minimal — optimizers only |
